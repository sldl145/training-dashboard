How to Update the Dashboard

The three workflows - gym session, body scan, run. Everything happens from your phone. Back to the dashboard

Start here - every workflow begins the same way

Open the Claude app → Code → new session on training-dashboard
  1. Pick the training-dashboard environment (not Default) when starting the session.
  2. Say what happened: "update dashboard", "new InBody scan", or "log a run".
  3. The session takes it from there - it will tell you if it needs anything.
One session can handle all three at once ("gym session done, and here's a run from yesterday"). Everything publishes to the live dashboard automatically at the end.

🏋️ Gym Session

Training tab - lifts, sets, PRs, goals
You bring: nothing to upload. The PT logs every set in Hevy during the session, and the dashboard fetches it from Hevy directly. Just bring your memory of how it felt.
1
Train at SATS
PT logs all sets in Hevy during the session - this is the ground truth.
YouHevy
2
Open a Code session → "update dashboard"
On the phone, whenever suits - same evening or next morning.
YouClaude Code
3
Debrief chat
How it went, what the PT said, any pain signals. The session writes your journal page to Notion (Session #XXX with Journal / Flags / Decisions / Context).
YouClaude CodeNotion
4
Data pulled from Hevy and cross-checked
Every number verified against the actual Hevy sets - Hevy always wins. Dashboard data, notes, and goals updated with targeted edits.
Claude CodeHevy
5
Checks pass → published
Data validator + real-browser render check must both pass, then the session pushes and the live page updates in ~60 seconds. Decisions get checked off in Notion.
Claude CodeLive dashboard

📊 Body Scan (InBody)

Body Composition tab - weight, muscle, fat %, InBody score
You bring: a photo of the InBody result sheet. Take it with your phone camera right at the machine, then attach it in the session chat (the + / attach button, same as sending any photo).
1
Scan at SATS, photograph the results
The printed sheet or the machine screen - either works.
YouInBody
2
Open a Code session → "new InBody scan" + attach the photo
The session reads all metrics from the image (Score, Weight, SMM, BFM, PBF, BMI, VFL, WHR) and asks what you want: log it, update the dashboard, or discuss the numbers first.
YouClaude Code
3
Logged to Notion, photo attached
New row in the InBody Scan Log (skips duplicates), your photo attached to the row, and a Scan #XX analysis page if you discussed the results.
Claude CodeNotion
4
Dashboard updated → published
The scan joins the trend charts and KPI cards; checks pass; live in ~60 seconds.
Claude CodeLive dashboard

🏃 Run

Running tab - half marathon prep, readiness score, pace trends
You bring: a screenshot of the workout summary from the Fitness app on your phone (the screen with distance, time, pace, heart rate). Attach it in the session chat.
1
Run with the Apple Watch
Afterwards, open the Fitness app, find the workout, screenshot the summary.
YouApple Fitness
2
Open a Code session → "log a run" + attach the screenshot
The session extracts distance, duration, pace, HR, elevation, calories, and classifies the run (easy / tempo / long / interval / race). Quick chat about how it felt.
YouClaude Code
3
Written to the Notion Running Log
Entry with data, notes, and any flags (weekly volume jumps get flagged automatically). Duplicates skipped.
Claude CodeNotion
4
Dashboard updated → published
Readiness score, alerts, milestones, and next week's targets all recompute automatically; checks pass; live in ~60 seconds.
Claude CodeLive dashboard

📅 Month Rollover

Closing one month and opening the next - goals, month summary, new Notion page
You bring: yourself, and about ten minutes. This one is a conversation - the session needs you to confirm which goals landed, and to sign off the new month's targets before they go live.
1
Open a Code session on (or just after) the 1st → "new month"
One session does the whole rollover. If you also trained that day, the rollover happens first and the session gets logged after.
YouClaude Code
2
Last month's goals reconciled
Every target checked against the logged sets first, then confirmed with you - hit, missed, or superseded. Data before memory.
YouClaude Code
3
Month summary written to Notion
The narrative record of the month: consistency, headline wins, what didn't happen, and what carries forward. A month isn't closed until this is written.
Claude CodeNotion
4
New month page created + new goals calibrated
Targets are worked out from your actual logged sets - trend fitted per lift, adjusted for travel and days you'll actually train, and aimed at roughly a coin flip. Hard, but genuinely reachable. You see them and can change any of them before they're written.
Claude CodeNotion
5
Dashboard goals updated → published
The new targets land in the Goals section with their status; checks pass; live in ~60 seconds. If no goals are agreed, the section says so rather than being padded out.
Claude CodeLive dashboard
Fallbacks, so nothing ever blocks: if Hevy can't be reached, the session asks you to paste a screenshot of the workout from the Hevy app instead. If you'd rather debrief in regular Claude Chat (on the metro, say), that works too - Chat writes the journal to Notion and the next Code session picks up the unchecked decisions. Duplicates are always detected and skipped.
